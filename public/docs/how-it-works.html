How GET /api/signal turns a Tradier snapshot into one call

Traced directly from strategy.service.js, indicators.service.js, greeks.service.js and news.service.js. Two tracks feed direction — technicals and news — and a third, options-chain quality, only ever dampens that direction. Every formula below is quoted from the actual code, not a generic pattern.

01

tradier.service.js fetches directly on POST /api/refresh or the 3-minute background loop; the signal endpoint then reads whatever snapshot is already on disk.

02

Score each dimension independently

Technicals and news form the direction in computeSignal (strategy.service.js). Options conditions never touch direction — it's a separate multiplicative dampener, computed by computeOptionsScore.

indicators.service.js

8 indicators computed, 7 vote

Each voter casts one vote in [-1, 1]; the average of whichever votes exist (not a fixed denominator) is scaled ×100.

RSI14 → continuousMACD 12/26/9 → ±1SMA20 vs 50 → ±1 Bollinger 20,2 → ±1/0Stochastic 14,3 → ±0.3–1VWAP → ±0.5ADX14 ±DI → ±0.75
RSI vote = rsi<30 ? +1 : rsi>70 ? -1 : (50 - rsi) / 20 // continuous 30-70 ADX vote = adx>=25 ? (+DI>-DI ? +0.75 : -0.75) : 0 score = (Σ votes / votes.length) × 100

StochRSI is computed but deliberately excluded — code comment: would "triple-count" RSI momentum. VWAP vote is skipped entirely on the 1d interval (no intraday session).

techScorelabels: ≥40 strong_buy · ≥12 buy · ≤-12 sell · ≤-40 strong_sell
relevance.service.js + news.service.js

Headlines, relevance-weighted

Per-symbol keyword tiers, word-boundary regex. Items scoring <25 relevance are discarded before scoring direction.

phrase overrides ±2~25 bullish words~25 bearish wordsGemini overlay (optional)
relevance = min(100, round( topWeight + 0.5×Σ otherWeights)) dirScore = clamp(phraseScore + sign(pos-neg)×min(|pos-neg|,5), -5, 5) overall = Σ(dirScore/5 × relevance) / Σ relevance × 100

Pool = relevant items if ≥5 exist, else all gathered items. If GEMINI_API_KEY is set, a 1-call batch analysis races an 8s timeout and overwrites these fields on success (analysisSource: "gemini").

newsScorebullish >10 · bearish <-10
strategy.service.js · computeOptionsScore

Penalty-only dampener

From the nearest 3–10 DTE chain (a stricter internal window than the 3–15 DTE fetch window): ATM IV, avg bid/ask spread, ATM open interest.

IV > 35% → penaltyspread > 2% → penaltyOI < 100 → flat 20
pIv = clamp01((atmIv-0.35)/0.35) × 50 pSpread = clamp01((spr-0.02)/0.08) × 30 pOi = liquidityOk ? 0 : 20 optionsScore = -min(100, pIv+pSpread+pOi)

Always ≤ 0. IV saturates the full 50pt penalty at 70% IV; spread saturates the full 30pt penalty at 10%. liquidityOk fails open (true) when no OI data exists at all.

optionsScorerange [-100, 0]
03

Combine into one verdict

computeSignal, strategy.service.js line ~161. This is not a 3-way weighted average — options conditions multiply, they don't add. The multiplier ranges 0.5×–1.0×, so a bad chain can halve conviction but never flip the direction tech+news already set.

The combine step — verbatim from strategy.service.js
directionalScore = techScore × 0.75 + newsScore × 0.25 combinedScore = directionalScore × (1 + optionsScore / 200)

Worked example — strong bullish setup, but a rich/thin chain: techScore 55, newsScore 40 → directionalScore 51.25. If optionsScore is −40 (elevated IV, wide spreads) the multiplier is (1 + −40/200) = 0.8 → combinedScore 41. Still buy_call — just less confident than the raw technicals suggested. A greeks-free snapshot leaves optionsScore at 0, multiplier 1.0, no change at all.

BUY PUTcombinedScore ≤ −30
HOLD−30 < score < 30
BUY CALLcombinedScore ≥ 30

Threshold is RISK.minSignalScoreToTrade = 30 — the same RISK object (strategy.service.js) that governs position sizing, stop-loss (35%), take-profit (60%), and max open positions (3). There's no separate "sell" action on an open position — that's decideExits, driven by stop-loss/take-profit, not this score.

04

newsVsOptions — side-channel inside computeSignal, never touches combinedScore/action

computeOptionsBias (greeks.service.js) finds the 25-delta call/put (0.15 delta tolerance), reads IV skew and put/call OI ratio, then assessDivergence compares that bias to newsScore.

skewBias = clamp(-100,100, -(ivSkew - 0.03)/0.05 × 100) // baseline put-skew 0.03 oiBias = clamp(-100,100, -log2(oiRatio / 1.2) × 100) // baseline put/call OI 1.2 bias = 0.7×skewBias + 0.3×oiBias (or whichever exists alone)
Aligned

sign(newsScore) === sign(bias) — news and options positioning lean the same way.

Divergent

Bullish news + bearish bias → contrarian caution on calls. Bearish news + bullish bias → downside could be sharp, puts relatively cheap.

Neutral

|newsScore| < 10 or |bias| < 15 (DIVERGENCE_NEWS_MIN / DIVERGENCE_BIAS_MIN) — not enough conviction on one side to compare.

computeSignal's response also bundles volSurface (25Δ/10Δ skew, term structure, vol risk premium) and gammaExposure (net dealer GEX, zero-gamma strike) — both computed the same call, both purely informational.

05

decideTrade — turns the verdict into an order

Runs only when autopilot is enabled and signal.action !== "hold", after guard checks: daily loss ≤ −15% blocks, 3 open positions blocks. GET /api/greeks's preview panel runs the same picker year-round, win or lose, just to show what would be picked.

Expiration — pickExpiration

  1. Walk 3–10 DTE candidates nearest first (the stricter internal window, not the 3–15 DTE fetch window).
  2. Skip any where ATM dailyThetaPctAtm > RISK.maxDailyThetaPct (0.06) — too much daily decay.
  3. Unless it's the last candidate in the window — then use it anyway rather than return nothing.

Strike — pickStrikeByDelta

  1. Discard strikes with OI < RISK.minOpenInterest (100) or spread > RISK.maxSpreadPct (0.10).
  2. Of what survives, pick |delta| closest to RISK.targetDelta = 0.40.
  3. No delta data at all → pickStrike fallback, 1%-OTM by price (otmPct = 0.01).

Position size

  1. qty = floor(min(equity × RISK.maxPositionPctOfEquity (0.35), cash) / (mid × 100))
  2. Autopilot runs on a 1-minute tick, per-symbol isolated $10k paper portfolio.

Exit — decideExits

  1. Runs every tick regardless of enabled state — stop-loss RISK.stopLossPct (0.35), take-profit RISK.takeProfitPct (0.6).
  2. Not driven by combinedScore at all — purely P&L-based on the open position's mark.
